# Request-bound KV batches

Branch `codex/bft-transfer-batched-storage` adds `kv_store_multi_get_bounded` for small groups of opaque records. It uses the existing `KvMultiGet` wire method and host implementation. Before a request, the enclave checks nonempty table/key fields, at most eight keys, each value maximum of at most 1 MiB, and aggregate maxima of at most 1.5 MiB. This fits the default 2 MiB control queue including request/response framing. A response must have the exact requested count, each requested maximum, valid presence tags and no trailing bytes. The host count never selects vector capacity. Storage callers must still authenticate every envelope and exact associated data; bounds grant no authority, durability or freshness.

The legacy unbounded wrapper remains unchanged. This change claims only the new request-bound path, not a review of all legacy KV callers. Raw RPC allocation still has the existing shared-queue bound, and a malicious host can deny availability. Write batching reuses the existing staged `KvWriteBatch`; its reply is never a durable receipt. Callers must read back every record and use a later ordered synchronous write before publishing a usable root or custody receipt.

The existing `rpc::tests::test_kv_multi_get_roundtrip` body now checks bounded roundtrip, request/count mismatch, excessive individual/aggregate limits, every truncated prefix, trailing data and a substituted maximum host count. Exactly one body executes out of the unchanged 123 common library identities. Native result PASS (`mini-bounded-kv-native-1`, log SHA-256 `e02b280ca88d6770699329b74eb746c136b457689f14b5a0702c1082f2345a68`). SGX compilation and fresh signed execution are still pending; this is not physical evidence or release qualification.

The corresponding honest-ehds branch is `codex/bft-transfer-remediation`. It groups the existing sealed upload page, bounded chunk parts and intermediate prefix, checks every readback and preserves the final ordered publication barrier and incoming client custody. It releases encoding inputs before grouped readback and charges additional temporary buffers against recovery lookahead. Stored formats, Wasmtime, cryptographic providers and host wire methods are unchanged. Reduced round-trip count is the intended benefit; achieved throughput must come from the fresh candidate's measured file oracle.
