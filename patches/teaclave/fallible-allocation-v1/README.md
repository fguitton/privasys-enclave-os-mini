# Fallible allocation SDK source profile

This default-off source profile adds an explicit fallible allocator ABI to the
pinned SDK and makes Builder name, thread/packet/closure and native task-node allocations return an error.
It does not enable a global allocator, replace the C allocator, or qualify total
TLS, thread, futex or heap accounting.

The manifest binds original and patched files plus patch bytes. Apply it only to
a new task-owned copy of the already reviewed SDK source; verify every before
file, patch hash and after file. Keep the original SDK and qualified sysroot
unchanged. Cargo and the std build must use the same copy.

CMake must include all manifest paths, including the new allocator module, plus
the manifest and patch hashes in the sysroot input identity before this profile
is selected. Its new input ID must own fresh std outputs. A reused historical
sysroot cannot establish this profile. The optional CMake selector verifies the exact afterimages and leaves the
default allocator behavior unchanged. Changes to CMake provenance still require
a fresh input identity; old binary identities are never relabelled.

The explicit allocator admits the complete backend layout, including its private
header and alignment padding, before allocating. Reallocation admits the full
new block while the old block remains live. Deallocation frees backend storage
before releasing the original owner and loan. Admission callbacks must be
nonallocating, non-unwinding and valid until the final deallocation. These are
resource rules, not application or signing authority.

The native model and allocator API checks are private development evidence.
They do not substitute for actual SDK/std compilation, connected constructors,
signed SIM or the original trusted runtime owning checks. The manifest's
remaining items must close before enforcement or final allocator qualification.

Reproduce source acquisition with the tracked helper:

```sh
python3 scripts/prepare-fallible-allocation-sdk.py \
  --source /absolute/reviewed-sdk-source \
  --identity /absolute/pinned-sdk-git-checkout \
  --destination /absolute/new-build/sdk-source
```

Configure that build with `HONEST_TEACLAVE_FALLIBLE_ALLOCATION_V1=ON` and
`HONEST_PINNED_TEACLAVE_FALLIBLE_SOURCE=/absolute/new-build/sdk-source`.
The selected source must be inside this build directory. The original identity
checkout still supplies the pinned tree enumeration; the selected mirror and
additional manifest files supply actual hashes. Cargo's acquired dependency
configuration must select this same mirror, and the compiler namespace must
mount it read-only. A mismatched source or old sysroot must fail; this is not an
SDK fallback. Only build `sgx_sysroot` until the partial profile's source and
provider/consumer joins qualify.

Before configuring a read-only compiler mirror, run the adjacent
`prepare-inputs.sh MAIN_SOURCE ORIGINAL_SDK NEW_AUTOTOOLS_OUTPUT` with
`approved-functions.sh` alongside it. These are the exact previously reviewed
network-off Autotools generation and refusal owners, tied to their source/tool
hashes. The receipt describes input generation; its historical SIM wording is
not a claim that a new HW or SIM compiler has run.

Mount only the receipt's libunwind subtree read-only over the owned SDK mirror,
set `HONEST_TEACLAVE_PREGENERATED_AUTOTOOLS=1`, and pass
`HONEST_TEACLAVE_FALLIBLE_AUTOTOOLS_RECEIPT=.../input-receipt.json`. CMake checks
all generated bytes and incorporates their receipt and actual paths into the
new std input identity. Generated source, input provenance and std outputs stay
separate. Neither the original checkout nor its historical sysroot is changed.
